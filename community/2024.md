  * [build.yml](https://github.com/bpfman/bpfman/blob/main/.github/workflows/build.yml) is building bpfman binary using cargo for x86 and [cross](https://github.com/cross-rs/cross) for non-x86 builds. cross uses a container to build the other architectures. Needed cross because of openssl.
  * [image-build.yaml](https://github.com/bpfman/bpfman/blob/main/.github/workflows/image-build.yaml) is trying to build a bpfman container image using the github action `docker/build-push-action@v6` which uses [Containerfile.bpfman](https://github.com/bpfman/bpfman/blob/main/Containerfile.bpfman) as the build container. I was trying to call cross from within Containerfile.bpfman, but we have a DinD setup and cross fails with “no container engine found \- Suggestion: is docker or podman installed?”.
    * I haven’t found anyone building with cross in a Container because you need the docker.sock file mounted in the build container. You can run something like:
      (See [https://github.com/cross-rs/cross/wiki/FAQ\#docker-in-docker](https://github.com/cross-rs/cross/wiki/FAQ#docker-in-docker)):
      $ docker run \-v /var/run/docker.sock:/var/run/docker.sock \\
        \-v .:/project \-w /project my/development-image:tag \\
        cross build \--target mips64-unknown-linux-gnuabi64
      But this is a `docker run` command. I need a `docker build` command and it doesn’t have a `-v` option.
    * [https://github.com/cross-rs/cross/issues/1530](https://github.com/cross-rs/cross/issues/1530)
  * Current workaround in [bpfman-PR\#1234](https://github.com/bpfman/bpfman/pull/1234) is in image-build.yaml, build bpfman binaries within image-build.yaml (same as build.yml), and the Containerfile.bpfman just copies binaries into the container. That works for upstream, but OpenShift is using Konflux and needs a fully contained Containerfile to build the image.
