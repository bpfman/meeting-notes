Agenda:

* Triage
* \[Billy\] Discuss details of [Allow specification of "map-pin-path"\#521](https://github.com/bpfd-dev/bpfd/issues/521):
  * Since an eBPF program can have multiple maps, is this providing a directory or a particular map?
    * Directory
  * Are we allowing any directory or does it have to be in “/run/bpfd/fs/maps/\<UUID\>/”? i.e. Are we forcing one program to load and create the map, then additional programs attach OR have multiple programs that want to share a map load and first one in creates and the rest attach?
    * The original intent was the first case (one loads and others attach to map) to address Maryam’s use case. The second case is more user friendly (which is a goal of bpfd) but needs more of the infrastructure around mounting filesystems in containers. See if the first case solves Maryam’s issue and if so, do that and follow up later with better implementation.
* \[Andre\] kprobes and retprobes
  * [.fini section after main](https://github.com/compilepeace/BINARY_DISSECTION_COURSE/blob/master/ELF/SECTION_HEADER_TABLE/SECTIONS_DESCRIPTION/SECTIONS_DESCRIPTION.md#fini)
  * [libbpf disallows offsets in kretprobes](https://github.com/libbpf/libbpf/blob/ec6f716eda43fd0f4b865ddcebe0ce8cb56bf445/src/libbpf.c#L10668), but not uretprobes.
